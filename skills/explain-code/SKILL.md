# 讲清楚一段代码

## 什么时候用

用户说「这段代码是干嘛的」「我看不懂这个函数」「解释一下这个文件」的时候。

## 步骤

1. **先定位，不要先读全文。**
   用 `grep` 找这个函数/类被谁调用，用 `list_dir` 看它在项目里的位置。
   一个函数的真正含义，一半在调用方那里。

2. **读，但只读必要的范围。**
   30 行以内直接读；超过 100 行就先读签名和注释，再决定跳过哪几段。
   读的时候记下三样东西：输入是什么、输出是什么、它改了哪些外部状态。

3. **找「为什么」。**
   代码里最费解的地方通常是历史原因。看 git 提交信息、看有没有注释解释，
   找不到就明说「这里看不出为什么这么写」。

4. **给结论，从大到小。**
   先一句话说这段代码在整个项目里干什么，再说它内部怎么实现。

## 输出格式

- **一句话**：它是什么、干什么用的。
- **怎么运转的**：3~5 步，每步一行，按真实执行顺序写。
- **输入和输出**：什么进来、什么出去、失败了会怎样。
- **值得注意的地方**：边界情况、隐藏的副作用、看着奇怪但可能有原因的写法。
- **看不懂的地方**：直接说哪几行没看懂，不要糊过去。

## 纪律

- 不要复述代码。用户能看见代码，他要的是解释。
- 不要用「显然」「众所周知」。读者就是因为不显然才问的。
- 猜的部分要标明是猜的。

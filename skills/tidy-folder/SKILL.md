# 整理一个目录

## 铁律

**先报告，后动手。** 用户说「整理一下」不等于授权你删东西。
第一步永远是列出清单让他看，等他确认哪一类可以动。

## 步骤

1. **摸清结构**：`list_dir` 打开 depth=2，看清楚有几个子目录、大概多少文件。

2. **扫一遍垃圾**：`scan_junk` 找出缓存、临时文件、安装包残留。
   这一步只返回清单，不会删任何东西。

3. **分类**：把文件按「一眼能看出用途」的维度分组。常见分法是
   文档 / 图片 / 压缩包 / 代码 / 其它，但不要硬套 —— 按用户的实际用途分更好。

4. **报告，然后停**：
   - 有多大的空间可以释放；
   - 哪几类建议删、哪几类建议归档、哪几类建议保留；
   - 有没有看着可疑但不确定的文件（这些一律标「待你确认」）。

5. **确认后才执行**：
   - 删除一律用 `delete_file` / `remove_junk`，它们走回收站，能还原；
   - 移动/重命名一个一个来，不要批量脚本；
   - 每做完一批就报告一次结果。

## 绝对不能做的

- 不要碰 `.git`、`node_modules`、`.venv`、`__pycache__` 之外的隐藏目录（那些除外，它们本来就是垃圾）；
- 不要删任何名字里带「备份」「bak」「final」「old」的文件 —— 那通常是用户最需要的；
- 不要在用户没确认的时候删任何东西。

## 收尾

报告清楚：删了什么（多少）、移了什么（到哪）、还剩什么建议用户自己看。
